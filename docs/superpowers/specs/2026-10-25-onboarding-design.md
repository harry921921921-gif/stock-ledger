# 第一次使用引導：一步一步把資料記進來

2026-10-25 · 使用者已確認流程樣稿（`docs/superpowers/mockups/onboarding.html`）；標「我的判斷」的是 Claude 的決定，使用者可以推翻

## 1. 目的

新帳號第一次登入就落在總覽，畫面全是 0，使用者不知道第一步該做什麼（2026-10-24 使用者回報：「才來到首頁這個畫面」就卡住）。
另外，現有頁面的輸入順序有前後關係，例如質押要先有持股才能勾擔保股票、用借款買股票要先有借款，使用者不會知道。

這個功能要讓使用者照固定順序一筆一筆記：**帳戶 → 借款 → 股票 → 擔保 → 完成**。記完回到總覽，數字就都出來了。

使用者的要求（原話整理）：
- 流程要順，畫面一次只出現一個。
- 按「上一步」之後，**已經填的資料要一直記得，不可以重新填**（2026-10-25）。
- 外觀之後再美化，這次沿用現在的樣式（app.css）。
- 不記得成本的股票，平均成本填大概的就好，不另外做「帶入收盤價」按鈕（2026-10-24）。

## 2. 目標、不做、絕對不能發生

**目標**
- 帳號還沒完成引導時，登入後（`GET /`）自動進入引導。
- 每一步都能略過；中途離開，下次登入從離開的那一步接著做。
- 每一步都有「← 上一步」，回去時看得到已經存的資料，可以直接在引導裡修改。

**不做**
- 前端美化（之後另外做）。
- 上櫃股票（等 DR-049 實作，引導第 3 步自然就能用）。
- 引導完成後，從設定頁重新打開引導（我的判斷：使用者沒要求；要清空重來時由管理者處理）。
- 融資（系統還沒做）。

**絕對不能發生**
- 同一筆資料記兩次。例如按上一步再按下一步，帳戶又被建一次。
- 引導有一套和正式頁面不同的規則。例如引導裡能存、股票頁卻擋下的資料。引導一律呼叫現有的 Service，驗證規則只有一份。
- 填到一半按上一步，回來要重填。

## 3. 流程與畫面

照樣稿。每一步是一個獨立網址，上方有步驟列（1 帳戶、2 借款、3 股票、4 擔保、5 完成：做完的綠色、略過的劃線、目前的藍色）。

| 網址 | 畫面 | 動作 |
| --- | --- | --- |
| `/welcome` | 歡迎：說明順序 | 「開始」→ 帳戶；「我自己來，不用引導」→ 標成完成、回總覽 |
| `/welcome/accounts` | 帳戶表單（名稱、類型、銀行或券商、現在的餘額、哪一天的餘額）＋已加入的帳戶清單 | 「加入這個帳戶」可以連續加；至少有一個證券交割戶，「下一步：借款」才能按 |
| `/welcome/loans` | 還沒記借款：問「你有拿去投資的借款嗎？」（有／沒有，略過）；記過：已記清單＋「再記一筆」「沒有了，下一步：股票」 | 略過 → 股票 |
| `/welcome/loans/new` | 借款表單，欄位同現在的新增借款（還款方式、這是股票質押、撥款日、金額、利率、依方式出現的欄位、往來帳戶、開辦費） | 質押不在這裡勾擔保股票，畫面註明「擔保股票等記完股票再設定」 |
| `/welcome/stocks` | 股票表單＋已記清單。記法二選一：「一次買進」（日期、股數、成交價、交割戶、資金來源）／「目前持有」（開始記帳日期、總股數、平均成本、資金來源） | 「儲存」可以連續記；「股票記完了，下一步」；「略過」 |
| `/welcome/collateral/{loanId}` | 只有記了質押才出現，每筆質押一頁：持股清單勾選、擔保股數（預設全部持股）、提醒線 150、追繳線 130 | 「儲存」→ 下一筆質押或完成；「之後再設定」略過這筆 |
| `/welcome/done` | 記了幾個帳戶、幾筆借款、幾檔股票 | 「到總覽看看」→ 標成完成、回 `/` |

每一頁另有「先離開，下次再繼續」：直接回總覽，引導進度保留，下次登入從這一步開始。

### 3.1 文字（照樣稿）

- 帳戶餘額說明：「填存摺或 App 上現在看到的餘額就好。這天以前的借款和買股票，不會再從這個餘額扣一次。」（DR-047）
- 「目前持有」的平均成本說明：「券商 App 的庫存頁有『成本均價』；查不到就填今天的收盤價，報酬率會從今天開始算。」
- 「一次買進」：「手續費系統會自動算，和對帳單不同再到股票頁修改。」
- 資金來源：「用借款買的就選那筆借款；一部分借款、一部分自己的錢，之後可以在股票頁拆。」

## 3.2 儲存和下一步分開（2026-10-25 使用者試樣稿後要求）

使用者試樣稿時發現：一定要按「儲存」才能往下走，結果存了一堆不需要的資料；打完字連按空白鍵也會直接換頁。所以：

- **「儲存」和「下一步」是兩個不同的按鈕。**「下一步」只換頁，不儲存。每一步底下固定是「先離開，下次再繼續」（左）和「下一步 →」（右）。
- **儲存前先確認**：按「儲存」先跳出確認視窗，列出這筆所有看得到的欄位和填的內容（沒填的顯示「（沒填）」），按「確認儲存」才真的存；按「回去修改」回到表單。存好後表單清空，這筆出現在上方「已儲存」清單，可以再記下一筆。
- **按「下一步」或「上一步」不跳任何視窗**，表單裡打到一半的字原樣留著（例如名稱打了「玉山」，回來還是「玉山」），不用整筆儲存（2026-10-25 使用者第二次試樣稿後要求，取代原本「有沒存的內容就先問」的視窗）。
- **已儲存清單每一筆旁邊有「修改」**：按了把那筆的內容放進表單，按鈕變成「儲存修改」和「取消修改」，表單上方提示「正在修改已儲存的資料」。儲存修改一樣先跳確認視窗。修改前打到一半的新內容先收起來，改完或取消後自動放回表單。
- **借款到期日檢查**：到期日早於或等於撥款日 → 不能存（錯誤）；到期日已經過了 → 欄位下方立即顯示紅字提醒，確認視窗裡也列出，但仍可以存（我的判斷：可能是還沒記的展延；提醒文字是「如果已經還清，這筆就不用記；如果有展延，請填展延後的到期日」）。正式版由 `LoanService` 驗證，畫面只顯示 Service 回傳的訊息，不在模板裡判斷。
- **鍵盤不會誤觸**：輸入框裡按 Enter（包含注音輸入法選字）不送出表單；換頁後焦點放在標題，不留在按鈕上；確認視窗打開時焦點在「回去」，所以連按空白鍵或 Enter 都不會儲存或換頁。只有用滑鼠（或 Tab 移到按鈕上）按按鈕才會儲存或換頁。
- 借款不再有「還有其他借款嗎？」那一頁：借款頁上方是已儲存的清單，下面是表單，記完一筆可以接著記，全部記完按「下一步」。帳戶、股票、擔保同樣的版面。
- 帳戶頁要至少「已儲存」一個證券交割戶，「下一步」才能按。
- **沒填完就不能存**（2026-10-25 使用者試樣稿時發現沒填價格也存進去）：按「儲存」時必填欄位有空的，視窗標題是「還有欄位沒填好，不能儲存」，用紅字列出「還沒填：價格」這類項目，只有「回去修改」一個按鈕，打的字都留著。必填和正式表單一致：帳戶（名稱、銀行或券商）；借款（名稱、銀行、借款金額、年利率、往來帳戶，加上依還款方式的扣款金額、扣款日、總期數或繳息日、到期日）；股票（代號、日期、股數、價格，買進加交割戶）。開辦費、初始餘額、資金來源有預設值或選填。正式版的必填與錯誤由 DTO 驗證和 Service 回傳，畫面只顯示。
- 因此資料庫裡不會有「存了但不完整」的股票，不需要「未完成、先不列入計算」的狀態（2026-10-25 和使用者討論後的做法；使用者原本提議存了但不算，Claude 建議改成不能存，理由是每個計算都要排除未完成狀態容易漏）。

### 3.3 頁面最上方的提醒（2026-10-25 使用者要求）

這些提醒固定顯示在該頁標題下方，條件消失就自動不見；文字與條件由 Service 判斷，模板只顯示：
- **引導還沒完成**（`onboarding_step` 不是 `DONE`）：總覽、股票頁、資金來源頁顯示「第一次使用引導還有沒完成的步驟」，點了回到引導那一步。
- **質押還沒設定擔保股票**（沒作廢的質押借款，沒有任何擔保股票列）：股票頁和資金來源頁顯示「『玉山質押』還沒設定擔保股票，維持率無法計算」，每筆一行，點了到那筆借款設定擔保的地方。

## 4. 上一步與「記得資料」（2026-10-25 使用者要求）

分成兩種資料：

1. **已經按「儲存」的**：存進資料庫，是真正的帳戶、借款、交易。回到那一步時，清單照樣顯示，每一列旁邊有「修改」，在同一頁的表單裡改（呼叫現有的 update，交易修改照樣寫 trade_revision；修改原因由引導自動填「第一次使用引導修改」——我的判斷）。下一步不會重新建立，所以不會重複。
2. **填到一半、還沒按儲存的**：按「上一步」「下一步」或「先離開」時，都把這一頁表單目前的內容暫存起來，不跳視窗；回到這一頁時自動填回去，按「儲存」成功後清掉。按「修改」某一筆已儲存的資料時，草稿另外收好，改完或取消後放回表單。
   - 我的判斷：暫存放在伺服器的 HttpSession（每個使用者、每個表單一份），不存資料庫。理由：只是輸入到一半的草稿，不是事件，不該進資料庫（CLAUDE.md「只儲存原始事件」）；放 session 不必寫 JavaScript。代價是登出或 session 逾時（30 分鐘）後草稿就沒了，已儲存的資料不受影響。
   - 因此「上一步」和「先離開」是送出表單的按鈕（POST，帶 CSRF token），不是單純的連結。伺服器收到後只存草稿、不驗證、不建立資料，再轉到上一頁。

「上一步」的去處固定（我的判斷，伺服器端用固定順序，比照樣稿使用者走過的路線）：帳戶 → 歡迎；借款（問題或清單）→ 帳戶；借款表單 → 借款；股票 → 借款；擔保 → 上一筆質押的擔保頁，第一筆則回股票；完成 → 最後一個擔保頁，沒有質押就回股票。

## 5. 記錄進度

- `app_user` 加一欄 `onboarding_step VARCHAR(20) NOT NULL`，值是 `WELCOME`、`ACCOUNTS`、`LOANS`、`STOCKS`、`COLLATERAL`、`DONE`，加 CHECK 限制。用新的 Flyway migration（實作時接續當時最後一個版本；上櫃 DR-049 也要一個 migration，看哪個先做）。
- 這是畫面進度，不是財務資料，所以不違反「只存原始事件」（記進決策紀錄 DR-050）。
- migration 給既有帳號預設值：**有任何現金帳戶的帳號 → `DONE`**（已經在用，不打擾）；完全沒有資料的 → `WELCOME`。新建立的帳號一律 `WELCOME`。
- 使用者往前走到某一步就更新這欄；按上一步不往回改（我的判斷：中途離開再回來，從走得最遠的那一步開始，已存的資料都在）。
- `GET /`：`onboarding_step` 不是 `DONE` 就轉到那一步的網址。其他頁面（側欄選單）照常可以進去，不強迫。
- 使用者要求測試前先清空他自己帳號的資料（2026-10-24），清空後把他的 `onboarding_step` 設成 `WELCOME`。清哪個帳號、清哪些表，動手前再跟使用者確認一次。

## 6. 程式放在哪裡

- `controller/OnboardingController`：只負責畫面與轉址，不計算、不碰 Repository。
- `service/OnboardingService`（`@Transactional`）：
  - 讀寫目前登入者的 `onboarding_step`（user_id 只從 Spring Security 取得）。
  - 「加入帳戶」在同一個交易裡呼叫 `CashAccountService.create` 和 `CashMovementService.setOpening`（餘額沒填就只建帳戶）。
  - 借款、股票、擔保分別呼叫 `LoanService.create`、`TradeService.create`、`LoanService.setCollateral`／`setThresholds`；修改呼叫各自的 update。
  - 完成頁的數字（帳戶數、借款數、股票檔數）由 Service 算好給畫面。
- 草稿：一個小的 session 物件（例如 `OnboardingDrafts`），比照現有的 `controller/FormTokens` 放在 controller 層。
- 模板 `templates/onboarding/*.html`，沿用 app.css，加少量步驟列樣式；表單欄位盡量重用現有表單的片段（Thymeleaf fragment），避免兩份。
- 沒有新的計算公式，不需要新的 Calculator。

## 7. 測試（先寫測試）

- 新帳號登入 `GET /` 轉到 `/welcome`；`DONE` 的帳號看到總覽。
- 加入帳戶會建立帳戶和初始現金餘額；回上一步再前進不會多建；沒有交割戶不能進借款。
- 借款、股票在引導裡存的規則和正式頁面一樣（例如股數超過持股的擔保會被擋，訊息相同）。
- 擔保頁只為質押出現；沒有質押時股票的下一步直接到完成。
- 「上一步」帶著填到一半的表單，回來時欄位還在；儲存後草稿清掉。
- 進度只往前；「先離開」後下次 `GET /` 回到同一步。
- 別人的借款 id 放進 `/welcome/collateral/{loanId}` 會回 404（沿用 NotFoundException）。
- migration：有帳戶的既有帳號是 `DONE`，沒資料的是 `WELCOME`。

## 7a. 審查後補充的決定（2026-10-25，實作者角度審查提出，以下都是 Claude 的判斷）

1. **確認視窗由伺服器產生，規則只有一份。** 按「儲存」先 POST 到「預覽」端點：伺服器用 DTO 驗證，再呼叫各 Service 新增的「只驗證、不存」方法（`LoanService.validate`、`TradeService.validate`、`CashAccountService.validate`，和存檔共用同一段檢查程式），有錯就把表單畫回來並列出錯誤（等於「還有欄位沒填好」）；沒錯就畫出確認畫面，列出所有欄位與提醒，按「確認儲存」才真的存（帶 FormTokens，按兩次也只存一筆）。
   - 和樣稿的差別：確認是伺服器畫的畫面區塊，不是 JavaScript 彈出視窗；「到期日已過」的紅字在按儲存後的確認畫面出現，不是邊打邊出現。功能相同，但不用把規則再寫一份 JavaScript。
   - 鍵盤：表單不靠 Enter 送出（按鈕用 `type="button"` 以外的方式時，用一小段 JS 擋掉輸入框裡的 Enter），換頁後焦點放在標題，確認畫面焦點在「回去修改」。這是唯一需要的 JavaScript。
2. **到期日規則正式頁也一起改**：`LoanService` 的檢查改成「到期日不能早於或等於撥款日」（原本只擋早於），並新增「到期日已經過了」的提醒（不擋存檔，做法比照現有的 `paymentWarning`）。正式的新增借款頁跟著有一樣的規則和提醒。
3. **進度**：進到某一步的頁面就把 `onboarding_step` 更新到那一步（只往前不往後），不管有沒有存資料。回到 `COLLATERAL` 時，進第一筆還沒設定擔保股票的質押；都設定過就進第一筆。
4. **提醒線、追繳線**：擔保頁儲存時，只有數值和目前生效的值不同才呼叫 `setThresholds`（每次呼叫都會多一個 RateSetting 版本）。
5. **引導完成後**：`/welcome/**` 一律轉回 `/`。頁面最上方「質押還沒設定擔保股票」的提醒，連到資金來源頁那筆借款的擔保設定（現有功能），不連回引導。
6. **所有資料都要能修改**（2026-10-28 使用者決定：「所有資料都是要能夠修改的，一定要有修改的地方」）。帳戶、初始現金餘額、股票交易、擔保股票現在就都能改；唯一的缺口是借款：
   - 現在 `LoanService.edit` 不能改類型、還款方式；新撥款一建立就有撥款異動，所以撥款日、借款金額從建立起就鎖住；利率只能加新版本。
   - 改成：借款的每個欄位隨時都能改（引導裡、資金來源頁都一樣），不限引導期間。改了合約資料（撥款日、金額、還款方式、利率、期數、扣款金額、扣款日）時：
     - 撥款那筆現金異動跟著改，寫修改紀錄（cash_movement_revision）。
     - 系統自動記的每期還本、利息：使用者沒手動改過的，依新資料重算並寫修改紀錄；使用者改過（照銀行數字）的保留不動，存檔後列出「這幾期你改過，沒有自動重算，請確認」。（2026-10-28 使用者同意）
     - 還款方式也能改，同樣依新方式重算自動記的期數。（2026-10-28 使用者同意）
     - **借款改小、不夠支付已經用它買的股票**（2026-10-28 使用者決定，部分修改 DR-044）：存檔前先跳提示「借款金額小於已經用它買股票的金額，差 N 元」，列出受影響的交易。使用者按「確定修改」後，差額改算成自己的錢（自有）：從最後買的那筆開始，把那幾筆交易的「借款出的錢」往下調，每筆寫 trade_revision。
       - 使用者原話是「從活存帳戶裡面扣除」。說明：買股票的錢當初已經從交割戶扣掉了，所以不再另外扣一次（再扣就重複扣款），只是把這部分的來源從「借款」改成「自己的錢」；系統本來就把不是借款的部分都算自有（DR-044）。這個說明已經在對話裡告訴使用者，計畫前再確認一次。
       - 「從最後買的開始調」是 Claude 的判斷（比照先買的先用借款的直覺）；提示畫面會列出每筆要調多少，使用者看了不同意可以按「取消」自己去改交易。
     - 「修改利率」和「新增利率版本」分開：修改是改正打錯的原始利率（改第一個版本），新增版本是之後真的調整利率。
   - 這會動到資金來源頁的正式功能，所以實作計畫裡排在引導之前，自己一個步驟、自己的測試；寫進決策紀錄 DR-051。
