# 總資產頁（第一版：現金）設計

2026-10-21 · 依與使用者的需求討論整理。標「（我的判斷）」的是 Claude 的決定，使用者可以推翻；其他都是使用者說的。

## 1. 為什麼要做、要解決什麼

使用者想知道**每個月自己的資產多了還是少了多少，原因是什麼**。「生活上錢夠不夠用」不在這個系統要解決的問題內（2026-10-21 使用者更正）。

所以「每月變動」看的是**淨資產**：
- 股價漲跌（帳面）、賣出損益、配息都算增加或減少；利息是減少。
- **借錢不算增加**：借 100 萬放進帳戶，總資產和負債一起多 100 萬，淨資產不變；負債那邊看得到就好。

總資產頁回答兩件事：**錢現在放在哪裡、各占多少**，以及**這個月淨資產變了多少、為什麼**。

## 2. 已經決定的事

1. **每月看淨資產變動**，取代規格原本的「每月收支」（只算經常性收入與支出、不含股票增值）。總覽與總資產頁的「本月淨現金流／本月現金淨流入」卡片都改成「本月淨資產變動」，並拆出原因。
2. **初始資金**：每個現金帳戶可以輸入一筆「開始用系統時帳戶裡本來就有的錢」（金額＋日期）。它是起點，**不算收入、不算存入、不算本月變動**。概念和股票的「期初持股」相同。
3. **資產配置排行**：每一檔股票和每一個現金帳戶，依金額由大到小排，顯示金額與占總資產 %，並提示最大單一部位（和設計稿 Assets 一樣）。
4. **慢慢做、慢慢加**：這一版只做現金；股票市值先顯示 0（「尚未有持股」），股票功能完成後再補上。
5. **對帳差額改叫「餘額調整」**，不再分成「生活支出／其他收入」。
6. **固定收支頁保留**（薪水、保險、訂閱等固定項目清單），但不再拿來算每月變動。（我的判斷：這一版不動它。）
7. **交易紀錄**：股票頁設計稿已有「最近賣出」與「全部交易紀錄」，會逐筆列出買賣與每筆賣出的賺賠（平均成本法）。屬於股票階段，這一版不做。
8. 畫面依設計畫布 https://claude.ai/artifact/WHJdwUeLPEoAYjHKAtiuXx 的「總資產」（Assets）設計稿，風格沿用 DR-012「穩健明亮」與目前的 app.css（前端美化排在之後）。

## 3. 這一版要做的（目標）

### 3.1 現金異動（「記一筆現金異動」）
- 類型：**存入**（錢從系統外進來，例如薪水入帳）、**領出**（錢離開系統，例如花掉、轉給別人）、**帳戶互轉**（系統內，兩個帳戶之間）。
- 欄位：日期、帳戶（互轉時是轉出帳戶與轉入帳戶，不能相同）、金額（> 0，方向由類型決定）、說明（可不填，例如「薪資入帳」，最多 100 字）。
- 只能選自己的帳戶；別人的帳戶 id 一律當作不存在（回 404）。

### 3.2 初始資金
- 每個帳戶最多一筆；在帳戶的編輯畫面或總資產頁的帳戶卡片上填寫（我的判斷：帳戶編輯畫面）。
- 欄位：金額（≥ 0）、日期。
- （我的判斷）其他現金異動的日期不能早於該帳戶的初始資金日期；沒有初始資金的帳戶從 0 開始。

### 3.3 輸入實際餘額（對帳）
- 選帳戶、日期（預設今天）、輸入實際餘額。
- 系統算出「系統餘額」（到那天為止所有異動加總），差額 ＝ 實際 − 系統，畫面上顯示成一筆「餘額調整」。
- **存的是使用者輸入的「實際餘額」，差額每次都重新推算**（我的判斷）。理由：規格 7.2「只儲存原始事件」，使用者輸入的是實際餘額；之後補記、修改或作廢更早的異動時，對帳過的餘額仍然正確，只是那一筆餘額調整的金額（和那個月的變動）會跟著改，這和規格 4.9-3「過去月份的數字可能隨之改變」一致。修改一筆對帳 ＝ 修改當時輸入的實際餘額。
- 同一帳戶同一天只能有一筆對帳（我的判斷）；計算順序：同一天先算完其他異動，再算對帳。
- 差額為 0 也要記一筆（我的判斷），這樣「上次對帳日期」才會更新。
- 超過 30 天沒對帳的帳戶，畫面提醒（spec 4.6-6）；以今天（Asia/Taipei）計算。從沒對帳過的帳戶，從初始資金日期起算；沒有初始資金就從帳戶建立日起算（我的判斷）。
- 餘額可以是負數（我的判斷）：不擋，但畫面用紅字並提示「餘額為負，請確認是否漏記存入」。交割戶在買進交割前後本來就可能暫時不足，擋下來反而記不進去。

### 3.4 修改與作廢（spec DR-020、CLAUDE.md）
- 現金異動、初始資金、對帳都可以修改或作廢；**不硬刪除**。
- 依規格 4.9：每次修改或作廢，先寫修改紀錄（時間、使用者、事件、**每個改到的欄位一列：欄位、舊值、新值**、原因），再更新原紀錄；作廢用旗標，作廢的不計入任何金額。
- 原因可以不填（我的判斷：家用系統，強制填寫只會讓人亂打）。
- 修改紀錄**不可用多型關聯**：規格第 6 節 EventRevision 寫「事件類型與 id」，但 CLAUDE.md 與 DR-019 禁止多型關聯，所以每種事件各自一張紀錄表、各自外鍵（例如現金異動的修改紀錄只指向現金異動）。這點要在規格第 6 節一併修正。
- 有修改過的異動，在列表上顯示「曾修改」標記（規格 4.9-3）。

### 3.5 總資產頁（依設計稿 Assets）
1. **四張數字卡片**
   - 總資產 ＝ 股票 ＋ 現金（這一版股票為 0）。
   - 股票：0，副標「尚未有持股」。
   - 現金：所有帳戶餘額合計，副標「N 個帳戶，占總資產 X%」。
   - **本月淨資產變動**：這一版只有現金部分，拆成「存入 ＋X、領出 −Y、餘額調整 ±Z」；初始資金與帳戶互轉都不算。副標註明「股票、配息、利息完成後才會完整」。
2. **資產配置**：這一版只列各現金帳戶（金額、占比、最大單一部位）。
3. **現金帳戶卡片**：帳戶名稱、類型、餘額、上次對帳日期與當時差額、超過 30 天的提醒、「輸入實際餘額」按鈕。
4. **最近的現金異動**：最新 10 筆，欄位：日期、帳戶、內容（類型＋說明）、金額（正負號）；右上「全部異動」連到完整列表。
5. **全部異動頁**：可依月份篩選，可從列表進入修改或作廢。
6. 左側選單的「總資產」改成可以點。

### 3.6 每月變動怎麼算（我的判斷，寫成純 Java 的 Calculator）
- 月份以 Asia/Taipei 的日曆月計。
- 本月現金變動 ＝ 本月所有「存入」− 本月所有「領出」＋ 本月所有「餘額調整」。
- 不計：初始資金、帳戶互轉、作廢的異動。
- 之後的階段會加上：股價漲跌（月底市值 − 月初市值 − 本月買進 ＋ 本月賣出的成本）、賣出損益、配息、利息。

## 4. 不做的（這一版）
- 股票、股價抓取、配息、借款、利息、總覽頁、交易紀錄。
- spec 4.6-5（對帳時列出預估已發放但未入帳的配息）：要等配息功能。
- 固定收支頁的任何修改、匯出 CSV、前端美化。

## 5. 絕對不能發生的（反目標）
- 初始資金被算成存入或本月變動，讓第一個月看起來「大賺」。
- 帳戶互轉被算成變動（只是左手換右手）。
- 任何人看到或改到別人的帳戶與異動。
- 硬刪除資料；修改後找不回原本的值。
- 金額用 double／float，或除法沒指定進位方式。

## 6. 限制（CLAUDE.md 與規格）
- 金額 `BigDecimal`、資料庫 `DECIMAL(19,4)`；日期 `DATE`／`DATETIME`，不用 `TIMESTAMP`。
- 只儲存原始事件；餘額、每月變動都由事件推算，不另存結果。
- 個人資料表都有 `user_id` 外鍵＋索引；`user_id` 只從 `CurrentUser` 取得；Repository 只提供帶 `userId` 的查詢。
- 所有關聯都建外鍵；不用多型關聯。
- Schema 只能用新的 Flyway migration（目前最新 V4）。
- Controller 不呼叫 Repository；Controller 與模板不做計算；公式寫成純 Java Calculator 並有單元測試。
- 防連點：表單載入 `/js/app.js`，送出按鈕有 `data-busy-text`；伺服器端也要能擋重複送出。現金異動沒有「名稱不可重複」這種自然的限制（同一天存兩筆一樣的錢是正常的），所以伺服器端用**一次性表單代號**（我的判斷）：每次打開表單產生一個代號放在 session，送出時檢查並用掉，同一個代號第二次送出就不再新增、直接回到列表。不需要新資料表。

## 7. 規格書要跟著改的地方（實作計畫的第一步：先給使用者看、同意後寫入，再開始寫程式）
- 名詞定義：新增「淨資產變動」「初始資金」「餘額調整」；「每月收支」改寫或移除。
- 3 頁面規格：總覽、總資產的「本月淨現金流／本月現金淨流入」改為「本月淨資產變動」；固定收支頁說明不再計入每月變動。
- 4.3 每月收支：改寫成每月淨資產變動的規則。
- 4.6：加入初始資金；第 3、4 點的「生活支出／其他收入」改成「餘額調整」。
- 第 6 節：EventRevision 改成「每種事件各自一張修改紀錄表」，拿掉「事件類型與 id」（多型關聯）。
- 第 8 節：新增 DR-031（每月看淨資產變動，取代每月收支）、DR-032（初始資金；對帳存實際餘額、差額推算為「餘額調整」）、DR-033（修改紀錄每種事件一張表，不用多型關聯）。
