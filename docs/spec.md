## 1. 目標與範圍

v1 要回答兩個問題：**借來的錢現在變成什麼、值多少**，以及**每個月固定收入夠不夠付利息和固定支出**。系統有多個使用者，每人登入後只看得到自己的資料；在自己的電腦上執行，資料要能保存 50 年以上。

| 項目 | 版本 |
| --- | --- |
| 登入與多使用者（資料依使用者隔離） | v1 |
| 股票紀錄（期初持股、逐筆交易、配股、部分賣出、融資批次） | v1 |
| 現金帳戶、借款（融資、質押、信貸） | v1 |
| 資金來源標記 | v1 |
| 每月淨資產變動、利息、配息預估、報酬率、維持率 | v1 |
| 每日股價與除權息資料更新（證交所 OpenAPI，啟動時抓最新） | v1 |
| 網頁介面（電腦為主，手機可瀏覽） | v1 |
| Claude API 個股分析 | 之後 |
| 每日股價雲端存檔（GitHub Actions） | 之後，走勢圖的前提 |
| 總資產走勢圖 | 之後，必做 |
| 年化報酬率 XIRR | 之後 |
| 手機 App | 最終目標 |
| 試算工具、未來財務推估 | 之後 |
| 上櫃、興櫃、海外股票 | 不做，有需要再議 |

部署：系統要能從外網使用，但家裡電腦不會 24 小時開機，所以正式環境放雲端主機（平台待定）。程式與資料庫一律以 Docker 封裝（`docker compose`：app + MySQL），開發時在本機用同一套設定執行，之後搬到任何雲端主機都不用改程式（DR-025）。

技術：Java 21、Spring Boot、Spring Security、Thymeleaf、MySQL 8.4、Flyway、Chart.js、Docker。分層為 Controller → Service → Repository；單一物件的規則放在 Entity，公式放在獨立的 Calculator 類別（純 Java、不依賴 Spring）並附單元測試。

## 2. 名詞定義

同一個詞在全系統只有一個意思；畫面、程式、測試都用這裡的定義。

| 名詞 | 定義 |
| --- | --- |
| 使用者 | 可登入系統的人；所有個人資料都屬於某一個使用者（v1.2 新增） |
| 總資產 | 股票總市值 + 所有現金帳戶餘額 |
| 總負債 | 所有借款的未償還本金 |
| 淨資產 | 總資產 − 總負債（只計算，不儲存） |
| 槓桿比例 | 總負債 ÷ 總資產 |
| 資金來源 | 一筆錢的出處：「自有」或「某一筆借款」 |
| 來源標記 | 附在每批持股上的資金來源組成，例如自有 40%、信貸 A 60%；現金帳戶不記錄來源（v1.2 修正） |
| 尚未投入 | 某筆借款撥款後、還沒分配到任何買進的金額 |
| 期初持股 | 開始使用系統時一次輸入的既有持股（股數 + 平均成本，平均成本含買進手續費），每檔股票最多一筆 |
| 配股 | 股票股利入帳；股數增加、成本為 0 |
| 平均成本 | 目前持股的買進總成本（含手續費）÷ 持有股數；買進時重算，賣出時不變 |
| 融資批次 | 一筆融資買進產生的融資借款，賣出時逐批償還 |
| 自備成本 | 買進總成本（含手續費）− 未償融資金額；沒有融資時等於買進總成本 |
| 股票報酬率 | 持有中股票本身的價差報酬率，分母為買進總成本；不論錢從哪來都一樣（v1.2 新增） |
| 自備款報酬率 | 以自己實際拿出的錢計算的報酬率，分母為自備成本，並扣除融資應計利息，和券商 App 一致；沒有融資時等於股票報酬率（v1.2 新增） |
| 含息總報酬率 | 股票報酬率加上累計已領配息 |
| 已實現報酬率 | 賣出後以實際入帳金額計算的報酬率，同樣提供股票、自備款兩種口徑 |
| 加權平均利率 | 以各筆借款未償本金為權重的平均年利率 |
| 維持率 | 擔保品市值 ÷ 借款金額，用於融資與質押 |
| 淨資產變動 | 某段期間（通常是一個月）期末淨資產 − 期初淨資產；包含股價漲跌、賣出損益、配息、利息、存入、支出、餘額調整（v1.6）。借款撥款、還本金、買賣股票、帳戶互轉只改變資產形式，不算變動（v1.4） |
| 初始現金餘額 | 開始使用系統時，現金帳戶裡原本就有的錢（金額＋日期），每個帳戶最多一筆；它是起點，不算存入，也不算淨資產變動（v1.4） |
| 餘額調整 | 輸入實際餘額時，實際餘額 − 系統推算餘額的差額；由系統推算，不另外儲存（v1.4） |
| 資金移動 | 只改變資產形式、不改變財富的事件：買賣股票、借款撥款、還本金、帳戶互轉 |
| 生效日期 | 費率開始適用的日期；計算時取「交易日當天或之前、最近的一筆」 |

## 4. 業務規則

核心規則：只儲存原始事件（交易、資金異動），持股、餘額、淨資產、來源組成一律由事件推算。

### 4.1 資金來源標記

1. 借款撥款時，整筆記為該借款的「尚未投入」餘額。現金帳戶本身不記錄來源組成。
2. 買股時由使用者輸入資金使用方式（例如自有 40 萬、信貸 A 60 萬），預設單一來源 100% 自有，可拆分；系統只檢查加總等於成交總額，且各借款不超過其「尚未投入」餘額。
3. 使用者輸入的分配就是這批持股的來源標記；同一檔股票的來源標記為各批加總。支出、繳息、固定支出都不影響借款標記。
4. 賣股時，入帳金額全部記為自有；系統同時記錄各借款部分的已實現損益，用於計算借款淨賺。
5. 配息、配股依持股的來源比例分配。
6. 還本金 X 元時，先減少該借款的「尚未投入」餘額；不足的部分，按各持股中該借款的金額比例，把標記等額轉為自有（DR-017）。
7. 繳息不影響借款標記；不論用哪筆錢支付，都計入該借款的「已付利息」。
8. 融資與質押直接綁定擔保股票，可精確對應。

### 4.2 持股輸入

1. 兩種模式：期初持股、逐筆交易。
2. 同一檔股票的期初持股最多一筆，日期必須早於該股所有逐筆交易。
3. 期初持股的平均成本含買進手續費。
4. 期初持股與每筆買進的資金來源由使用者輸入：預設單一來源，需要時可拆成多個來源。
5. 配股：股數增加、成本 0、平均成本下降；也要計算二代健保（以面額每股 10 元計）。
6. 股票代號必須存在於證交所上市清單，否則拒絕輸入並提示。
7. 交易依股數判斷整股或零股（股數不是 1,000 的倍數即為零股），套用對應的最低手續費。

### 4.3 每月淨資產變動（v1.4 改寫，DR-031）

1. 本月淨資產變動 ＝ 本月底淨資產 − 上月底淨資產，畫面拆成：股價漲跌（帳面）、賣出損益、配息（扣二代健保後）、利息（負）、存入、支出、餘額調整（v1.6）。
2. 不算變動：初始現金餘額、期初持股（都是起點）；帳戶互轉、借款撥款、還本金、買進股票（只改變資產形式）。
3. 月份以 Asia/Taipei 的日曆月計算。
4. 補記、修改或作廢過去的事件後重新推算，過去月份的數字可能改變（見 4.9-3）。
5. 固定收支自動產生的異動和手動記的一樣計入（v1.6，DR-035）。

### 4.4 賣出與對帳

1. 賣出時由使用者輸入實際入帳金額；已實現報酬率以實際金額計算。
2. 系統同時計算預估入帳金額；兩者不同時顯示差異，作為對帳提示。

### 4.5 費率

1. 所有費率與門檻都附生效日期；計算時依交易日取適用值。
2. 變動時新增一筆新版本，不修改舊版本。
3. 法定費率（含二代健保費率與門檻）由 Flyway seed 預先寫入，所有使用者共用；個人費率（手續費折扣、最低手續費、各借款利率、維持率門檻）屬於各使用者，由使用者在網頁輸入。
4. 空狀態：缺少個人費率時系統照常運作，相關數字顯示「未設定」並連到設定頁。

### 4.6 現金帳戶與對帳

1. v1 帳戶類型：證券交割戶、銀行活存（含薪資帳戶）。定存、外幣延到之後版本。
2. 現金異動用一個入口「記一筆現金異動」：存入（系統外進入，記為自有）、支出（離開系統；v1.6 前稱「領出」）、帳戶互轉（系統內）。欄位：日期、轉出帳戶、轉入帳戶、金額、備註；依類型只顯示需要的帳戶：存入只有轉入帳戶、支出只有轉出帳戶、互轉兩個都有。生活費改由固定收支「每月自己填」的項目記錄（第 3 節第 5 頁）（v1.6，DR-035）。
3. 每個帳戶可以設定一筆初始現金餘額（金額＋日期），不算存入。手動記的存入、支出、互轉與對帳，日期不能早於初始現金餘額日期，也不能晚於今天。借款與股票交易自動產生的現金異動照真實日期記錄，早於初始現金餘額日期的只用來計算借款與股票，不影響這個帳戶的餘額，因為初始現金餘額已經包含它們（v1.9，DR-047）。
4. 日常花費不逐筆記錄；每個帳戶可「輸入實際餘額」。系統儲存使用者輸入的實際餘額，「餘額調整」＝實際餘額 − 系統推算餘額，每次由事件重新推算。同一帳戶同一天最多一筆。
5. 餘額調整計入淨資產變動，不再分成生活支出、其他收入（DR-032）。
6. 對帳畫面同時列出本期「預估已發放但尚未記錄入帳」的配息，避免漏記被當成餘額調整。
7. 超過 30 天未對帳的帳戶，畫面提醒；從沒對帳過的帳戶，從初始現金餘額日期（沒有就從帳戶建立日）起算。
8. 金額以整數元記錄；餘額可以是負數，畫面提醒是否漏記存入。
9. 全部異動頁可以搜尋備註：找出所有月份裡備註包含搜尋字的異動（不分大小寫、去掉前後空白；比對依資料庫的 collation，所以也不分重音，例如 cafe 會找到 café），新的在前；已作廢的也列出並標示「已作廢」；搜尋字最多 50 個字；搜尋框空白時照舊依月份瀏覽（v1.6）。

### 4.7 部分賣出（DR-016）

1. 現股部分採平均成本：賣出成本 = 平均成本 × 賣出股數；剩餘持股的平均成本不變。
2. 來源標記按比例減少：各來源減少的金額 = 該來源目前金額 × 賣出股數 ÷ 持有股數。
3. 融資部分逐批追蹤：預設償還最早的融資批次（先進先出），賣出畫面可手動改選，以券商對帳單為準。
4. 同一筆賣出同時有現股與融資時，使用者輸入各自的股數。

### 4.8 信貸利率變動（DR-018）

1. 信貸利率由 RateSetting 依生效日期提供。
2. 利率變動後的第一期起，以「剩餘本金、剩餘期數、新利率」重算月付金。
3. 每期利息 = 期初剩餘本金 × 月利率，進位到元（UP）；本金 = 月付金 − 利息；最後一期本金補足剩餘餘額。

### 4.9 事件修改紀錄（DR-020）

1. 交易與資金異動不硬刪除；刪除改為標記「作廢」。
2. 每次修改或作廢，先把修改前的內容寫入該事件的修改紀錄表（時間、使用者、事件、欄位、舊值、新值、原因），再更新原紀錄（DR-033）。
3. 修改後由事件重新推算所有結果，過去月份的數字可能隨之改變，畫面顯示「曾修改」標記。

### 4.10 使用者與登入（v1.2 新增，DR-022）

1. 使用 Spring Security 表單登入；密碼以 BCrypt 雜湊儲存，不存明碼。
2. 角色兩種：管理者、一般使用者。帳號由管理者在設定頁建立；忘記密碼由管理者重設。系統第一次啟動時建立初始管理者帳號。
3. 資料隔離：所有個人資料表都有 `user_id`；Repository 的每一個查詢都必須帶目前登入者的 `user_id`，Service 不可接受畫面傳來的 `user_id`。
4. 共用資料：上市股票清單、每日股價、除權息資料、法定費率由所有使用者共用。
5. 「記住我」有效 30 天；連續登入失敗 5 次鎖定 15 分鐘。
6. 帳號：比對時去掉前後空白（含全形空白）並轉小寫，所以 `Alice` 和 `alice` 是同一個帳號；帳號中間不可有空白或看不見的字元，最多 50 個字。（v1.3）
7. 密碼：至少 8 個字；BCrypt 最多處理 72 bytes（中文字每個算 3 bytes），超過時拒絕。管理者重設密碼會同時解除鎖定，舊的「記住我」失效；對方已登入中的連線不會被踢掉，閒置 30 分鐘後逾時。（v1.3）
8. 鎖定期間，不論密碼對錯都顯示「登入失敗次數過多，請 15 分鐘後再試」（DR-029）。（v1.3）

## 5. 計算公式與進位規則

所有計算用 `BigDecimal`。中間值保留 10 位小數、`RoundingMode.HALF_UP`；只有最後的金額依下表進位到元。每個公式各自一個 Calculator 類別，各有單元測試。

| 項目 | 進位到 | 方式 | 備註 |
| --- | --- | --- | --- |
| 手續費 | 元 | 無條件捨去（`DOWN`） | 最低手續費分整股（預設 20 元）、零股（預設 1 元），設定頁可改 |
| 證交稅 | 元 | 無條件捨去（`DOWN`） | |
| 二代健保 | 元 | 四捨五入（`HALF_UP`） | 費率與門檻來自 RateSetting |
| 利息 | 元 | 無條件進位（`UP`） | 融資、質押、信貸皆同 |
| 報酬率、比例、維持率 | 0.01% | 四捨五入（`HALF_UP`） | 只用於顯示 |

### 5.1 交易費用

```
手續費 = max( floor(成交金額 × 手續費率 × 折扣), 最低手續費[整股或零股] )
證交稅 = floor(賣出成交金額 × 證交稅率)
```

法定費率 seed：手續費率上限 0.1425%；證交稅率一般股票 0.3%、一般 ETF 0.1%、現股當沖 0.15%。債券 ETF 與當沖優惠有期限，實作 seed 時查證並附生效日期。

### 5.2 二代健保補充保費

單次股利（現金股利 + 股票股利面額）達門檻時扣繳。費率（目前 2.11%）與門檻（目前 20,000 元）都存於 RateSetting：

```
補充保費 = round(單次股利 × 補充保費率)
```

### 5.3 利息

```
融資、質押：利息 = ceil(借款餘額 × 年利率 × 天數 ÷ 365)
信貸月付金 = P × r(1+r)^n ÷ ((1+r)^n − 1)    r = 年利率 ÷ 12，P = 剩餘本金，n = 剩餘期數
加權平均利率 = Σ(未償本金_i × 年利率_i) ÷ Σ 未償本金_i
```

### 5.4 報酬率（v1.2 修訂，DR-023）

兩種口徑並列：**股票報酬率**看股票本身漲跌；**自備款報酬率**看自己拿出的錢賺多少，和券商 App 一致。沒有融資時兩者相同。

```
自備成本     = 買進總成本(含手續費) − 未償融資金額
股票報酬率   = (市值 − 買進總成本) ÷ 買進總成本
自備款報酬率 = (市值 − 未償融資金額 − 融資應計利息 − 自備成本) ÷ 自備成本
含息總報酬率 = (市值 + 累計已領配息 − 買進總成本) ÷ 買進總成本

已實現（股票）   = (賣出淨額 − 賣出部分買進成本) ÷ 賣出部分買進成本
                  賣出淨額 = 成交金額 − 手續費 − 證交稅
已實現（自備款） = (實際入帳金額 − 賣出部分自備成本) ÷ 賣出部分自備成本
```

兩種報酬率都不扣預估賣出手續費與證交稅，所以數字會略高於券商 App 的預估損益；股票頁加註說明。配息不併入股票、自備款報酬率，另列「累計已領配息」。

```
借款淨賺 = 持有中帳面損益 + 已實現損益 + 配息 − 已付利息
```

以上各項都只計算該借款出資的那一部分；融資的已付利息用累積應計利息。

利差：借款滿一年用「年化報酬 − 年利率」；未滿一年用「期間報酬 − 期間利息」。期間報酬 =（帳面損益 + 已實現損益 + 配息）÷ 未償本金。

預估入帳金額 = 賣出成交金額 − 手續費 − 證交稅 − 償還融資金額 − 融資利息（用於對帳）。

### 5.5 維持率

```
融資整戶維持率 = Σ 融資股票市值 ÷ Σ 融資金額
質押維持率     = 擔保股票市值 ÷ 質押借款餘額
```

### 5.6 配息預估

```
預估年配息 = 最近一期每股現金股利 × 年配息次數 × 持有股數
```

每期金額達二代健保門檻時先扣補充保費。股票股利另列，不併入金額。

融資買進是一筆 Trade：系統同時建立融資 Loan 與 MarginLot，並把融資金額記為這批持股的來源之一。

SourceAllocation 用兩個可為 null 的外鍵，加上 CHECK 限制恰好一個有值（MySQL 8.0.16 起支援 CHECK）：

```sql
CONSTRAINT chk_alloc_event CHECK (
  (trade_id IS NOT NULL AND cash_movement_id IS NULL) OR
  (trade_id IS NULL AND cash_movement_id IS NOT NULL)
)
```

為什麼不用「event_type + event_id」：那種多型關聯無法建立外鍵，程式寫錯時資料庫不會擋下，50 年後很難修。

## 7. 資料更新與長期使用

### 7.1 每日資料更新

股價與除權息資料只來自證交所 OpenAPI，由排程抓取；AI 不抓。系統在本機執行，所以必須處理「當天程式沒開」的情況。

1. 排程：交易日晚上固定時間抓取（`@Scheduled`），避開收盤後資料尚未整理完的時段。
2. 啟動抓取：程式啟動時若今天尚未更新，就抓最新一個交易日的股價與除權息資料。沒開機的日子不補抓股價；之後以 GitHub Actions 每日存檔補齊（DR-011）。
3. 日期檢查：回傳資料的日期必須等於要更新的交易日；不符就不寫入，留待下次重試。
4. 除權息：以證交所除權息資料為準（DR-024）；API 沒有的欄位（年配息次數）由使用者手動填。實作時確認可用的 API 端點。
5. 更新後重算：資料寫入後，由後端重新計算市值、報酬率、維持率、配息預估。
6. 紀錄：每次抓取寫一筆 PriceUpdateLog，總覽顯示「股價更新至 YYYY-MM-DD」。

### 7.2 長期使用：50 年以上

程式、電腦、框架都會換好幾次，**資料必須比程式活得久**。

| 項目 | 規則 |
| --- | --- |
| 日期型別 | 一律用 `DATE` / `DATETIME`，禁用 MySQL `TIMESTAMP`（上限 2038-01-19） |
| 時區 | `DATETIME` 一律存台灣時間（Asia/Taipei）；JVM 與資料庫連線都明確設定時區 |
| 金額型別 | 金額 `DECIMAL(19,4)`、股價 `DECIMAL(12,4)`、股數 `BIGINT`；Java 一律 `BigDecimal` |
| 主鍵 | 每張表用內部流水號；股票代號、名稱只是欄位；分割、減資、合併、下市、改代號延後，資料模型先預留 |
| 事件不可改寫 | 不硬刪除；修改與作廢都寫修改紀錄（見 4.9） |
| 外鍵 | 所有關聯都建立外鍵；多型關聯改用多個外鍵 + CHECK |
| 資料隔離 | 個人資料表一律有 `user_id` 外鍵與索引；查詢一律帶 `user_id`（見 4.10） |
| 安全 | 密碼 BCrypt；備份檔含所有使用者資料，存放位置要有存取限制 |
| 費率與法規 | 附生效日期（DR-005），稅率改變不影響歷史數字 |
| 商業邏輯 | Calculator 用純 Java、不依賴 Spring，並有完整單元測試 |
| 資料可攜帶 | 可匯出全部資料為 CSV（管理者匯出全部，一般使用者只能匯出自己的） |
| 備份 | 每日自動備份到雲端硬碟資料夾、保留 30 天；每年匯出完整 CSV；每年演練還原一次 |
| 效能 | 50 年約數萬筆交易、數十萬筆股價，MySQL 可輕鬆處理；重算變慢再加年度快照 |

## 8. 決策紀錄

| 編號 | 決定 | 原因 | 放棄的選項 |
| --- | --- | --- | --- |
